# بررسیِ UX/UI عمل‌یار (`ux-audit`)

> ترتیبِ تقدم مثلِ همیشه: حرفِ مالک → `CLAUDE.md` → `amalyar-design` → `ui-ux-pro-max` → این فایل.
> این اسکیل «چطور بررسی کنیم» است، نه «چه طراحی کنیم» — طراحیِ تازه همچنان «اکی»ِ مالک
> می‌خواهد (قانونِ ۲۶).

## ۱. روش — پنج گام

1. **محیطِ جدا با دادهٔ واقعی‌نما** — هرگز روی دیتابیسِ آزمون‌ها (نام‌های `684ac2`، فرم‌های
   خاموش‌شدهٔ سوییت‌ها) بررسی نکن؛ هر یافته‌ای که از دادهٔ آلوده بیاید دروغ است.
   ```bash
   # دیتابیس‌های تازه (نمونه: ux_t1 مطب، ux_t2 شرکت روی 127.0.0.2، ux_ctl)
   DATABASE_URL=…/ux_t1 CONTROL_DATABASE_URL=…/ux_ctl E2E_TENANT2_DATABASE_URL=…/ux_t2 \
   TENANT_DATABASE_ENCRYPTION_KEY=… node scripts/e2e/bootstrap-env.mjs
   # API یک پورت؛ دو Vite: 127.0.0.1:5600 → API 127.0.0.1، و 127.0.0.2:5601 → API 127.0.0.2
   # (CORS_ORIGINS و WEBAUTHN_ORIGINS هر دو مبدأ را بگیرند)
   UX_API_CLINIC=http://127.0.0.1:3502/api UX_API_COMPANY=http://127.0.0.2:3502/api \
   JWT_SECRET=… UX_OUT=/tmp/ux-audit node scripts/ux/seed-demo.mjs
   ```
   ⚠️ **تلهٔ ترتیبِ ماژول‌ها:** اگر نوعِ نصب پیش از اولین خواندنِ `/features` «مطب» شود،
   ماژول‌های شرکتی (چینش، پنلِ کارشناسی، حمل‌ونقل، انبار) روشن می‌مانند
   (`featureChanges` فقط ردیف‌های موجود را خاموش می‌کند). در محیطِ بررسی پیش از عکس‌برداری
   `GET /features` را بزن یا آن چهار ردیف را دستی خاموش کن.
2. **عکس + سنجهٔ ماشینی از همهٔ صفحه‌ها** — دو تم × ۱۲۸۰ و ۳۹۰ × تا سه بُرشِ اسکرول:
   ```bash
   UX_UI=http://127.0.0.1:5600 UX_API=http://127.0.0.1:3502/api UX_TAG=clinic  node scripts/ux/capture.mjs
   UX_UI=http://127.0.0.2:5601 UX_API=http://127.0.0.2:3502/api UX_TAG=company node scripts/ux/capture.mjs
   node scripts/ux/flows.mjs        # پاپ‌آپ‌ها، ویزارد، ترخیص، صفحه‌های عمومیِ بیمار
   ```
   سنجه‌ها **سرنخ‌اند نه یافته**: کنتراستِ تخمینی روی شیشه و گرادیان نویز دارد، و «هدفِ ریز»
   شامل پیوندهای درونِ متن هم می‌شود. هر عدد را با چشم روی عکس تأیید کن.
   ⚠️ `/auth/login` محدودیتِ نرخ دارد (۱۲ بار در ۱۵ دقیقه به‌ازای IP) — برای اجرای مکرر
   `UX_TOKEN` بده (کوکیِ نشست) و دوباره وارد نشو.
3. **نقدِ ناحیه‌به‌ناحیه با پرسونا** — پوسته و مدیریت · کارِ روزانهٔ مطب (منشی/پزشک) · مسیرِ
   جراحی (اتاقِ عمل، ترخیص، فهرستِ انتظار، فرمِ عمل) · عملیاتِ شرکت (صفِ ثبت‌نام، چینش،
   پنلِ کارشناس) · صفحه‌های عمومیِ بیمار. هر ناحیه را در **جریانِ کارِ واقعی** راه برو
   (نه فقط عکسِ ایستا): چند لمس؟ چه چیزی اول دیده می‌شود؟ خطا کجا گفته می‌شود؟
4. **یافته فقط با مدرک** — عکس یا خطِ کد. هر یافته: شدت (بحرانی/مهم/جزئی)، نوع
   (`bug` = شکسته/نادرست؛ `improvement` = طراحیِ بهتر)، قاعده (UX-n / WEB-n / WCAG / قانونِ n)،
   پیشنهادِ مشخص، مدرک. تکراری‌ها ادغام؛ سلیقهٔ صرف حذف.
5. **گزارش برای مالک** — بند‌به‌بند، فارسیِ ساده، هر بندِ دیداری با عکس. `bug`ها بی‌سؤال رفع
   می‌شوند (رفعِ باگ «اکی» نمی‌خواهد)؛ `improvement`ها با `AskUserQuestion` بند‌به‌بند
   (بماند / عوض شود / حذف شود) — قانونِ ۲۶.

## ۲. چارچوبِ نقدِ هر صفحه (design-critique)

1. **برداشتِ دوثانیه‌ای** — اول چه چیزی دیده می‌شود و آیا همان درست است؟ هدفِ صفحه روشن است؟
2. **کاربردپذیری** — پرسونا کارش را تمام می‌کند؟ گامِ اضافه؟ عنصرِ تعاملی آشکار است؟
3. **سلسله‌مراتبِ دیداری** — ترتیبِ خواندن، تأکیدِ درست، فضای خالی، مقیاسِ قلم.
4. **هم‌خوانی** — همان چیز همه‌جا همان نام/جا/شکل: سربرگ، «بازگشت»، منوی پروفایل، چیپِ
   وضعیت، تاریخ، مبلغ و «تومان»، نامِ کاشی = عنوانِ صفحه (قانونِ ۲۴)، واژهٔ حوزه از `useTerms()`.
5. **دسترس‌پذیری** — بخشِ ۳.

## ۳. WCAG 2.1 AA — آنچه در عمل‌یار واقعاً می‌شکند

| معیار | در عمل‌یار یعنی |
|---|---|
| 1.4.3 کنتراستِ متن ≥ ۴٫۵ (درشت ≥ ۳) | **در هر دو تم**؛ متنِ فرعی (`--text3`) روی شیشهٔ روشن اولین قربانی است |
| 1.4.11 کنتراستِ اجزای رابط ≥ ۳ | مرزِ فیلد و چیپ در تمِ روشن؛ دکمهٔ شبح |
| 1.1.1 / 4.1.2 نام و نقش | دکمهٔ فقط‌آیکون بی `aria-label` (سنجهٔ `unnamed`)؛ کشویی‌های `Pick` |
| 3.3.2 برچسبِ ورودی | جای‌نگهدار برچسب نیست (سنجهٔ `unlabeled`) |
| 2.4.7 فوکوسِ دیدنی | `focus-visible` روی هر کنترلِ تازه (قانونِ ۱۰) |
| 2.5.5 هدفِ لمسی ≥ ۴۴px | ردیفِ دکمه‌های آیکونیِ کارت‌ها روی موبایل |
| 1.4.1 رنگ تنها نشانه نباشد | وضعیت = رنگ + متن/آیکون |
| 3.3.1 شناساییِ خطا | خطا کنارِ همان فیلد، با راهِ اصلاح |
| 1.4.4 بزرگ‌نمایی ۲۰۰٪ | چیدمان نشکند؛ هیچ سرریزِ افقی در ۳۹۰ (سنجهٔ `overflowX`) |

## ۴. متنِ رابط (ux-copy) — فارسی

- **دکمه با فعل و نتیجه**: «ثبتِ عمل»، «ارسالِ پیامک»؛ نه «تأیید»/«ارسال» خالی.
- **پیامِ خطا = چه شد + چرا + چه کنم**: «تاریخِ عمل گذشته است — تاریخِ امروز یا بعد را بزنید».
- **حالتِ خالی = این چیست + چرا خالی است + از کجا شروع کنم** (نه فقط «—» یا «موردی نیست»).
- **پنجرهٔ تأیید** کارِ مشخص را نام می‌برد و پیامدش را می‌گوید؛ دکمه‌ها «حذفِ نوبت» / «نگه‌داشتن».
- واژهٔ حوزه («ویزیت/عمل/خدمت») از `useTerms()`؛ عنوانِ **فرم** («فرمِ جراحی») جای **نوع** را
  نمی‌گیرد؛ انگلیسیِ بی‌دلیل و اصطلاحِ فنی (API، CRM بی‌توضیح) در متنِ کاربر نه.

## ۵. تله‌های شناخته‌شده در همین بررسی

- عکسِ تمام‌صفحه نوارِ چسبانِ بالا را وسطِ تصویر می‌کشد — عکسِ هم‌اندازهٔ صفحه‌نما بگیر (`capture.mjs`).
- `JDate` تا وقتی فوکوس دارد رقمِ لاتین نشان می‌دهد و در blur فارسی می‌کند — باگ نیست.
- «امروز» و فهرست‌ها برای سوپرادمین «مالِ همه»اند (قانونِ ۲۹) — با دیدِ سطح ۲ هم بسنج.

## منبع

در افزونهٔ **Design** از مخزنِ `anthropics/knowledge-work-plugins` (مجوزِ Apache-2.0)، بومی‌شده
